# 原始版本问题清单

本清单以 `源文件` 中的原始文件为依据，记录的是改造前的可复现问题，而不是对作者的主观评价。每项均对应当前项目中的修复方向。
## P0：传输安全与密钥管理

1. **客户端关闭了服务器证书与主机名验证。** 原始 `client_script.py` 和 `client/client.py` 将 `check_hostname` 设为 `False`、`verify_mode` 设为 `ssl.CERT_NONE`。任何可中间人劫持本机连接的人都能伪装服务端。
2. **私钥以明文形式生成和保存。** 原始 `generate_cert.py` 使用 `serialization.NoEncryption()` 写出 `server.key`；原始目录同时存在多份 `.key` / `.pem`，增加误提交和泄露风险。
3. **证书路径和配置分散且不一致。** 根目录、`server/`、`client/` 中同时存在证书和多个 INI 文件，运行位置不同会读取不同文件，缺少唯一配置来源。

## P0：协议与服务端稳定性

4. **TCP 接收错误地假设一次 `recv(1024)` 就是一条完整消息。** TCP 是字节流；原实现会截断超过 1024 字节的消息，也可能把半条消息当完整请求处理。
5. **服务端只能串行处理一个连接。** 原始 `server/server.py` 在无限循环中直接处理客户端；慢连接会阻塞之后的所有请求。
6. **异常隔离不足。** TLS 握手、连接超时和请求处理异常可能跳出主处理流程；没有连接并发上限、帧长度限制或统一超时策略。
7. **业务逻辑只是字符串回显。** 仅对“你好”返回固定文本，其余直接拼接回显；没有结构化请求、响应状态、输入校验或业务错误分类。

## P1：账号、数据与权限缺失

8. **没有用户账户、密码哈希和登录会话。** 原版不存在注册、登录、注销、身份识别、管理员角色或会话失效机制。
9. **没有数据库持久化。** 用户、消息、审核状态和操作历史均不会保存；服务重启后没有可恢复的业务数据。
10. **没有权限边界。** 用户不能区分普通用户与管理员，也没有用户管理、重置密码、审核、屏蔽消息等控制能力。
11. **没有消息治理能力。** 不支持用户间私聊、管理员审核、违规消息屏蔽、审核原因和审计追溯。

## P1：界面与可用性不足

12. **客户端只有一个消息输入框与响应标签。** 没有登录、注册、联系人、对话历史、个人资料、管理员工作台或错误恢复界面。
13. **原 `client_gui.py` 只是“客户端运行中…”占位窗口。** 它与实际 TLS 客户端逻辑没有连接，容易造成运行入口混乱。
14. **运行参数硬编码。** 主机 `127.0.0.1` 和端口 `8081` 写在多处源码里，修改配置时容易遗漏。

## P1：日志与维护性问题

15. **日志策略不统一。** 原始文件混用根日志、独立日志器和不同文件名；有的日志级别为 `ERROR`，但关键成功/失败链路记录在 `INFO`，实际不会输出。
16. **日志文件位置与轮转规则不一致。** 服务端直接写根目录 `server_log.log`，没有统一生命周期和保密字段脱敏。
17. **缺少自动化测试与交付方式。** 原版没有覆盖证书、协议分包、权限、数据迁移或界面行为的测试，也没有安装包。

## 当前版本对应改进

当前版本采用双向证书校验、加密私钥、长度前缀协议、超时与受限并发；使用 MySQL 保存用户、会话、消息、资料、审核和操作日志；提供普通用户与管理员界面、个人中心、联系人职位分组和审核能力。完整能力与启动方式见项目根目录的 [README.md](../README.md)。
