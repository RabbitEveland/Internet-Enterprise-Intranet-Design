# Secure Messenger：PyCharm + MySQL 用户与消息系统

这是一个本机 TLS 客户端/服务端系统，不需要运行任何 XML 文件或 PowerShell 命令。MySQL 只由服务端访问；客户端只通过 TLS 登录、注册、联系管理员和与其他用户私聊。

> 改造前原版的可复现问题、风险及对应改进见 [原始版本问题清单](docs/ORIGINAL_ISSUES.md)。

## 已实现功能

普通用户可以：注册账户、登录、在个人中心设置头像、性别、职位与个人简介，查看与管理员的消息、发送新消息，并自动发现其他启用用户后发起双向私聊。

管理员可以：查看用户列表、搜索、新建账户、编辑用户名/角色/启用状态、删除账户、重置任意账户密码、查看某个普通用户的消息并回复。重置密码会立即清除该用户旧会话，强制其重新登录。

服务端首次启动会自动创建以下 MySQL 表：

| 表 | 用途 |
| --- | --- |
| `users` | 用户名、scrypt 密码哈希、角色、启用状态及个人资料（头像、性别认同、职位、简介） |
| `sessions` | 8 小时有效的登录会话；数据库只保存令牌哈希 |
| `messages` | 用户与管理员的支持消息，以及用户之间的双向私聊 |
| `message_moderation` | 每条消息的当前屏蔽状态、原因、操作人及时间 |
| `moderation_events` | 屏蔽与解除屏蔽的操作记录 |
| `operation_logs` | 登录、发送消息、账户管理、密码重置与审核等安全操作的审计记录 |

## 第一次在 PyCharm 中配置

### 1. 配置项目解释器

原 `.venv` 指向已经不存在的 `E:` 路径，不要继续使用。

1. 打开 **文件 → 设置 → 项目：大专毕业设计源代码 → Python 解释器**。
2. 点击 **添加解释器** → **添加本地解释器** → **Virtualenv** → **新建**。
3. 位置设为项目根目录下的 `.venv`；基础解释器选择 Python 3.10+；点击 **确定**。
4. 打开项目根目录的 `requirements.txt`，点击 PyCharm 显示的 **安装 requirements**。安装完成后应能看到 `cryptography` 和 `mysql-connector-python`。

### 2. 配置 MySQL 连接地址

确认本机 MySQL 服务已经启动。默认配置在 [config.ini](config.ini)：

```ini
[database]
host = 127.0.0.1
port = 3306
database = secure_messenger
user = secure_messenger_app
```

如果你的 MySQL 端口、数据库名或账号不是这些值，只改这四项；**不要把 MySQL 密码写进 `config.ini`**。

首次 `setup_mysql` 会创建 `secure_messenger` 数据库和专用账号；日常服务端账号只需要该库内的建表及增删改查权限。不要把 MySQL 密码写进 `config.ini`。

### 3. 使用已有 PyCharm 运行配置

如果 PyCharm 已经打开项目，先点 **文件 → 从磁盘重新加载全部内容**。右上角运行下拉框使用以下实际 Python 配置：

1. `setup_mysql`：仅第一次运行。它会在本机创建数据库和专用账号，并在弹窗中设置 root 与项目账号密码。
2. `generate_cert`：首次运行。它会弹两个窗口，让你设置并确认 TLS 私钥口令；成功后在 `runtime/` 生成加密私钥和开发证书。
3. `server`：每次先运行它。依次输入项目 MySQL 密码；若系统尚无管理员，还会要求设置“初始管理员用户名”和密码；最后输入 TLS 私钥口令。看到 `Server listening on 127.0.0.1:8081.` 即启动成功。
4. `client`：保持服务端运行，再运行它。会打开重新设计的登录界面。

三个口令输入框都不会把密码保存到 `config.ini`、日志或客户端。初始管理员只在数据库内尚不存在管理员时创建一次。

## Windows 安装包

本仓库附带已构建的安装向导：`installer-output\SecureMessenger-Setup.exe`。安装脚本为 [packaging/SecureMessenger.iss](packaging/SecureMessenger.iss)。安装向导默认安装到 `D:\SecureMessenger`，可在向导中改为其他位置；不会写入 C 盘，也不会安装、重置或修改 MySQL 服务。

安装完成后，开始菜单会有“启动服务端”“启动客户端”和“重新生成 TLS 证书”三个入口。先启动服务端并在弹窗中输入现有 MySQL 项目账号密码和 TLS 私钥口令，再启动客户端。安装包保留 `config.ini`、TLS 证书和加密私钥；升级安装时不会覆盖安装目录中已经存在的这三类配置文件。

如果要在另一台电脑使用，先自行准备 MySQL，并在安装后按实际地址修改安装目录根部的 `config.ini`；MySQL 密码依旧不写入配置文件。

## 使用界面

### 普通用户

登录页点击“创建新用户”，注册成功后会自动登录。左侧联系人会自动加载其他启用账户，普通用户与管理员并列显示，并按职位分组；点击任意联系人即可查看资料、发起双向对话。管理员也能在个人中心填写自己的资料，因此用户可像查看其他联系人一样查看管理员资料。

顶部“个人中心”可设置头像、职位、个人简介和性别。头像支持 PNG、JPEG、GIF，单张最大 512 KB。窗口底部的“保存个人资料（Ctrl+S）”会明确提交修改。

在联系人列表中选中其他账户后，点击“查看选中联系人资料”即可查看对方主动填写的头像、性别、职位和简介；普通用户可查看其他启用用户与管理员的资料，但自己的资料仍应在“个人中心”维护。

### 管理员

管理员登录后左侧是用户管理区，右侧是与选中用户的消息区：

- “新建 / 编辑 / 删除”完成用户增删改；
- “重置密码”要求输入两次新密码，并使该用户立刻下线；
- 选择一个角色为 `user` 的账户会自动加载对话；
- 在右侧输入消息并发送即可回复该用户。
- “对话审核 / 违规屏蔽”可查看用户之间及管理员会话的完整消息；选中用户后打开，会默认筛选该用户相关消息，也可取消筛选查看全部。
- “查看系统操作日志”可在软件内查询登录、消息发送、账户增删改、密码重置和消息审核的记录，无需打开 PyCharm。

审核窗口每页显示 40 条消息，按编号排序，可翻页。选中消息可查看完整原文，填写操作原因后点击“屏蔽选中消息”或“解除屏蔽”。审核操作会记录管理员、时间、原因和状态。

普通用户刷新或重新打开对话后，被屏蔽消息会显示“该消息因违规已被管理员屏蔽”；服务端不会把该消息原文返回给普通用户。管理员仍可查看原文复核，解除后用户可再次查看。这里的屏蔽针对单条消息，不禁止双方继续发送新消息；此前已收到的内容与既有本地日志不会被远程删除。用户私聊也属于管理员内容审核范围。

操作日志每页显示 50 条，可按操作账号、动作或说明搜索。它只保存操作账号、时间、成功/失败、目标编号与安全说明，**不保存密码、会话令牌或消息正文**。操作账号名会在写入时留存；删除账户不会删掉审计记录。

升级后重启 `server` 和 `client` 即可；服务端启动时会自动补齐个人资料、审核和操作日志相关字段并保留已有消息，**不要重新运行 `setup_mysql`**。

系统始终阻止删除自己、停用自己，或移除最后一个启用的管理员。

## 调试日志位置

| 文件 | 内容 |
| --- | --- |
| `server/server_log.log` | 服务端收到的请求和返回的响应，包含消息正文 |
| `client/client_log.log` | 客户端发送请求与收到响应，包含消息正文 |

这两份是通信调试日志：密码、密码哈希、会话令牌和头像数据会自动显示为 `<redacted>`，消息内容保留，并自动轮转。管理员日常查看业务操作应使用软件中的“查看系统操作日志”，无需打开这些文件或 PyCharm。

## 测试

在 PyCharm 左侧项目视图右键 `tests` 目录，选择 **运行“Unittests in tests”**。当前测试覆盖：

- TLS 证书校验、错误握手隔离和 TCP 分包；
- 密码 scrypt 哈希和日志脱敏；
- 注册、登录、用户联系管理员、管理员回复；
- 自动发现可联系用户、用户双向私聊与私聊权限限制；
- 管理员重置密码后旧会话失效。
- 审核权限、双方消息屏蔽、原文保留、解除屏蔽与分页；
- 审核窗口消息选择及操作按钮状态。
- MySQL 审计日志的权限、分页，以及密码和消息正文不入库。
- 个人资料、非二元/自定义性别认同、头像校验与头像日志脱敏。

测试不连接你的 MySQL；数据库与专用账号在 `setup_mysql` 中创建，实际业务表会在首次运行 `server` 时创建。

`test_moderation_mysql.py` 是单独启用的集成测试，默认跳过。在测试运行配置中设置 `MYSQL_TEST_BASEDIR` 为 MySQL 二进制目录、`MYSQL_TEST_TEMP_PARENT` 为 D 盘全英文临时目录父路径后运行；它会创建独立实例、验证旧表兼容和屏蔽持久化，结束后清理该临时实例，不访问业务数据库。
